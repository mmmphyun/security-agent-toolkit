### 이전 프로젝트에서 사용해 본 cloudflare dns, cdn 관련 질문과 그 답변

DNS (Domain Name System)

정의: 사람이 읽을 수 있는 도메인 주소(예: example.com)를 네트워크 통신에 필요한 컴퓨터의 IP 주소(예: 192.0.2.1)로 변환해 주는 '주소록(전화번호부)' 역할입니다.

동작 계층 및 범위: IP 라우팅 이전의 이름 해석(Name Resolution) 단계에서만 동작합니다. 데이터 전송 자체에는 관여하지 않으며, 단지 클라이언트가 목적지 서버의 IP를 알 수 있도록 돕습니다.

CDN (Content Delivery Network)

정의: 전 세계 여러 지역에 분산 배치된 에지(Edge) 캐시 서버를 통해 사용자와 지리적으로 가장 가까운 곳에서 웹 콘텐츠(정적 파일, API 응답 등)를 대신 응답해 주는 '분산 프록시/캐싱' 기술입니다.

동작 계층 및 범위: 실제 HTTP/HTTPS 트래픽 전달 과정에서 리버스 프록시(Reverse Proxy)로 동작합니다. 오리진 서버의 트래픽 부하를 줄이고 로딩 속도를 개선하며, 원본 서버의 IP를 숨겨 보안을 강화합니다.

Cloudflare가 두 기능을 모두 제공하는 이유

구조적 결합 (Reverse Proxy의 진입점): CDN이 동작하려면 사용자의 트래픽이 오리진 서버로 직접 가지 않고 CDN의 에지 서버로 먼저 들어와야 합니다. Cloudflare가 권한 있는 DNS(Authoritative DNS)를 제공하면, 도메인의 A/AAAA 레코드를 Cloudflare의 에지 IP로 자동 연결하는 프록시(오렌지 구름) 처리가 완벽하게 자동화됩니다.

성능 최적화: 자체 Anycast DNS 인프라를 사용해 전 세계 어디서든 수 밀리초 내에 DNS 쿼리를 처리하고, 동시에 사용자를 가장 가까운 에지 CDN 서버로 라우팅합니다.

보안 통합(WAF, DDoS 방어): DNS 단계에서 유효하지 않은 트래픽을 거르고, 에지 CDN 단계에서 WAF와 DDoS 공격을 흡수하여 오리진 서버의 실제 IP 노출을 원천 차단할 수 있습니다.

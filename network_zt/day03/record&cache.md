*3교시. DNS 레코드와 캐시 — 답의 내용과 유효 시간*


### 점검문제

1. IPv4 주소와 IPv6 주소를 각각 담는 레코드의 연결로 맞는 것은?

- A. IPv4는 AAAA, IPv6는 A
- **B. IPv4는 A, IPv6는 AAAA**
- C. 둘 다 MX
- D. 둘 다 NS

```
해설
- A. 두 레코드의 역할을 반대로 연결했다.
- B. A는 IPv4 주소, AAAA는 IPv6 주소를 담는다.
- C. MX는 메일을 받을 서버를 가리킨다.
- D. NS는 담당 네임서버를 가리킨다.
```

2. `www.example.com`의 CNAME 값이 `web.example.com`이다. 가장 알맞은 해석은?

- A. 값이 곧 IPv4 주소다.
- B. `www.example.com`이라는 이름은 존재하지 않는다.
- **C. 다른 이름인 `web.example.com`을 따라가 주소를 찾는다.**
- D. 메일 우선순위가 web이다.

```
해설
- A. CNAME 값은 다른 이름이며 IP 주소 자체가 아니다.
- B. 다른 이름을 가리키는 정보가 주어진 상황이다.
- C. 별칭 관계를 따라가 최종 주소 정보를 확인한다.
- D. 메일 우선순위는 MX 레코드와 관련된다.
```

3. MX와 NS의 역할을 올바르게 연결한 것은?

- **A. MX는 메일 수신 서버, NS는 담당 네임서버를 가리킨다.**
- B. MX는 웹 서버 IPv4, NS는 웹 서버 IPv6를 담는다.
- C. MX는 캐시 시간, NS는 웹페이지 경로다.
- D. MX와 NS는 모두 다른 이름을 가리키는 별칭이다.

```
해설
- A. 둘 다 서버 이름을 가리키지만 맡는 역할이 다르다.
- B. 주소 종류의 구분은 A와 AAAA에 해당한다.
- C. 캐시 시간은 TTL이며 웹페이지 경로는 이 레코드들의 값이 아니다.
- D. 일반적인 별칭 관계는 CNAME으로 표현한다.
```

4. 10:00에 TTL 300초인 답을 저장했다. 다시 저장하거나 갱신하지 않았다면 10:03의 남은 TTL은?

- A. 300초
- B. 180초
- C. 0초
- **D. 120초**

```
해설
- A. 저장한 뒤 경과한 180초를 빼야 한다.
- B. 180초는 경과 시간이며 남은 시간이 아니다.
- C. 300초 중 180초만 지났으므로 아직 만료 전이다.
- D. 300 − 180 = 120초다.
```

5. 권한 네임서버의 원본 IP를 바꿨는데 어떤 DNS 서버는 아직 이전 IP를 답한다. 가능한 정상 원인은?

- A. 원본 변경은 항상 즉시 모든 캐시를 지운다.
- **B. 이전 답이 아직 TTL 안에 있어 캐시에서 나온다.**
- C. IP가 다르면 예외 없이 공격이다.
- D. 도메인 이름을 쓸 수 없게 된 것이다.

```
해설
- A. 원본 변경이 다른 서버의 유효한 캐시를 곧바로 없애지는 않는다.
- B. 조회 시점과 남은 TTL에 따라 두 주소가 잠시 다르게 보일 수 있다.
- C. 승인된 변경과 캐시로도 주소 차이가 생긴다.
- D. 주소가 달라 보인다는 관찰만으로 그렇게 판단할 수 없다.
```

6. 캐시가 만료됐지만 새 질문은 없다. 미리 갱신하거나 만료된 답을 재사용하는 기능은 없다고 가정한다. 맞는 설명은?

- A. 만료 즉시 모든 PC에 새 IP가 전송된다.
- B. 이전 답을 영구히 계속 사용한다.
- **C. 기존 답의 사용 시간이 끝났으며 다음 질문 때 다시 조회한다.**
- D. 도메인 등록 자체가 취소된다.

```
해설
- A. TTL 만료는 전체 PC에 새 주소를 방송하는 동작이 아니다.
- B. 정해진 사용 시간이 끝났다는 조건과 맞지 않는다.
- C. 이 가정에서는 만료만으로 새 조회가 자동 발생하지 않는다.
- D. 캐시 유효 시간과 도메인 등록 기간은 다르다.
```

7. AAAA 조회에 NOERROR가 왔지만 원하는 IPv6 주소는 없다. 가장 적절한 해석은?

- **A. DNS 처리 오류 응답은 아니지만 원하는 주소가 있다고 보장하지는 않는다.**
- B. IPv6 주소가 반드시 하나 이상 있다.
- C. 웹페이지까지 정상적으로 열렸다는 뜻이다.
- D. 이름이 없다는 NXDOMAIN과 항상 같은 뜻이다.

```
해설
- A. NOERROR만으로 주소 존재나 웹 서비스 정상을 확정할 수 없다.
- B. 응답 상태와 실제 답의 내용을 함께 확인해야 한다.
- C. DNS 결과와 웹 접속 결과는 별도로 확인한다.
- D. NOERROR와 NXDOMAIN은 구분되는 상태다.
```

8. NXDOMAIN 응답과 DNS 질문 시간 초과의 차이는?

- A. 둘 다 이름이 없다는 답을 받은 것이다.
- B. 둘 다 웹 서버가 꺼졌다는 뜻이다.
- C. 시간 초과만이 이름이 없다는 공식 응답이다.
- **D. NXDOMAIN은 이름이 없다는 응답이고, 시간 초과는 응답을 받지 못한 상태다.**

```
해설
- A. 시간 초과는 그런 답을 받은 것이 아니다.
- B. DNS 조회 결과만으로 웹 서버 상태를 단정할 수 없다.
- C. 시간 초과는 정해진 시간 안에 응답을 받지 못한 관찰이다.
- D. 받은 답의 의미와 답을 받지 못한 상황을 구분한다.
```

9. SERVFAIL 응답을 받았다. 가장 알맞은 판단은?

- A. 해당 이름은 존재하지 않는다고 확정한다.
- **B. DNS가 조회를 정상 완료하지 못했으므로 원인을 더 확인한다.**
- C. 웹 로그인에 성공했다는 뜻이다.
- D. 캐시 TTL이 반드시 0이라는 뜻이다.

```
해설
- A. 이름이 없다는 NXDOMAIN과 구분해야 한다.
- B. 처리 실패를 나타내며 이 정보만으로 단일 원인을 확정할 수 없다.
- C. DNS 응답 상태는 웹 로그인 결과가 아니다.
- D. SERVFAIL만으로 특정 TTL 값을 알 수 없다.
```

10. 두 PC에서 같은 이름의 IP가 다르게 보인다. 공격 여부를 판단하기 위한 다음 행동으로 가장 적절한 것은?

- A. 주소가 다르므로 즉시 공격으로 확정한다.
- B. 어느 한쪽 웹페이지가 열리면 조사를 끝낸다.
- **C. 사용한 DNS 서버·조회 시각·TTL·원본·승인된 변경 이력을 대조한다.**
- D. 두 PC의 화면 크기를 비교한다.

```
해설
- A. 정상적인 변경이나 캐시 차이도 가능하다.
- B. 페이지가 열린 사실만으로 DNS 답의 정당성을 보장하지 않는다.
- C. 정상 변경과 캐시로 설명되는지 살펴보고 관찰과 추정을 구분한다.
- D. 화면 크기는 DNS 답 차이의 근거가 아니다.
```


### rpg-sync 프로젝트 당시 부족했던 지식을 이번 기회에 채우게 됨. 그땐 단순하게 생각하고 적용만 한 뒤 넘겼던 것들이 실무에서 어떤 의미가 있는지 조사해 봄.

1. R2 커스텀 도메인과 CNAME

R2 연결 시 생성된 assets -> public.r2.dev는 별명을 가리키는 CNAME 레코드임.

Cloudflare 프록시 덕분에 외부에서는 CNAME을 거쳐 최종 IP를 다시 찾는 추가 질의 없이, 에지 IP로 바로 연결됨.

2. TTL과 캐시 버스팅

DNS나 CDN 원본을 바꿔도 클라이언트·리졸버에 남은 TTL 동안은 무조건 이전 사본이 응답됨.

이 캐시 시차 문제를 해결하기 위해 배포 시 정적 자산 경로에 식별자를 붙이는 Cache Busting을 적용함.

3. 도메인 오타와 부정 캐시(Negative Cache)

도메인 철자가 틀리면 단순 통신 실패가 아니라 NXDOMAIN 응답이 옴.

리졸버가 이 '없다'는 결과도 일정 시간 캐싱(부정 캐시)하기 때문에, 설정을 고친 직후에도 바로 반영되지 않는 원인이 됨.

4. IP 불일치와 HTTPS 인증서 검증

DNS 조회 시 실제 GCP IP가 아닌 Cloudflare Anycast IP가 뜨는 것은 프록시의 정상 동작임.

혹시 DNS 스푸핑이나 캐시 포이즈닝으로 엉뚱한 IP를 받아도, 브라우저가 도메인과 TLS/SSL 인증서를 대조하므로 2차 검증 단계에서 연결이 차단됨.

*6교시. PDP와 PEP 서버 연결하기 — 판단을 요청하고 결과 적용하기*

PC의 문서 요청을 수신한 PEP 서버가 PDP 서버로 검증 요청을 전달하고 그 결과를 받아 클라이언트에 응답하는 과정에서 SuspensionError: Cannot call a function that blocks or suspends here 예외가 발생하며 처리가 중단되는 문제가 발생했다. 원인은 Cisco Packet Tracer의 Python 런타임(Skulpt 기반 인터프리터)이 지닌 단일 스레드 제약으로 인해, HTTPServer.route 핸들러 콜백 내부에서 네트워크 I/O 블로킹 작업인 동기식 requests.get()을 직접 호출하면서 실행 컨텍스트가 정지(Suspend)되었기 때문이다.

처음에는 내장 비동기 모듈인 http.HTTPClient로의 대체를 시도했으나, 런타임 환경 내 미지원 및 비정상 동작으로 인해 패킷 전송 자체가 이루어지지 않는 한계가 확인되었다.

이에 따라 핸들러 내부에서 외부 통신을 직접 수행하지 않고, 수신된 요청 컨텍스트(user, response)를 큐(리스트)에 즉시 적재한 뒤 핸들러를 곧바로 종료시키는 구조로 설계를 변경했다. 이후 메인 루틴(while True)에서 큐의 작업을 꺼내 이미 통신이 검증된 requests.get()으로 PDP에 질의하고, 최종 판단 결과에 맞춰 PC로 응답을 전송하도록 비동기 작업 큐 패턴을 적용하여 에러 없이 통신을 정상화했다.

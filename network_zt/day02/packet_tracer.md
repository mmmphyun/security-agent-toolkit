*5~6교시 시스코 패킷 트레이서 실습*


## 질의응답

Q. 서브넷마스크와 vlan 차이와 각각이 적용되는 범위, 사례
A. 
**1. 핵심 개념 차이**

* **서브넷 마스크(Subnet Mask): L3(네트워크 계층) 논리적 주소 분할**
* 하나의 IP 주소 체계 안에서 **네트워크 ID와 호스트 ID의 경계를 정의**하는 수학적 필터입니다.
* 단말(Host)이 통신 상대방의 목적지 IP를 보았을 때, "동일 네트워크(로컬 ARP 통신)인가, 아니면 다른 네트워크(디폴트 게이트웨이로 전송)인가?"를 판단하는 기준이 됩니다.


* **VLAN(Virtual Local Area Network): L2(데이터 링크 계층) 물리적 세그먼트 분할**
* 물리적인 L2 스위치 내부를 논리적으로 쪼개어 **브로드캐스트 도메인(Broadcast Domain)을 격리**하는 IEEE 802.1Q 태깅 기술입니다.
* 서로 다른 VLAN 간에는 스위치 레벨에서 프레임이 아예 전달되지 않으므로, 물리적으로 분리된 별도의 스위치를 사용하는 것과 동일한 효과를 냅니다.



**2. 비교 요약**

| 구분 | 서브넷 마스크 (Subnetting) | VLAN (IEEE 802.1Q) |
| --- | --- | --- |
| **OSI 계층** | Layer 3 (Network Layer) | Layer 2 (Data Link Layer) |
| **분할 대상** | IP 주소 공간 (IP Allocation) | 브로드캐스트 도메인 / MAC 학습 테이블 |
| **식별자** | 프리픽스 표기 (`/24`, `255.255.255.0`) | VLAN ID (1~4094, 12비트 태그) |
| **동작 장비** | 라우터, L3 스위치, 호스트 OS IP 스택 | L2 스위치, L3 스위치, 가상 스위치(OVS 등) |
| **격리 수준** | **소프트 논리 격리**<br>

<br>(IP를 수동 변조하거나 같은 L2에 있으면 패킷 스니핑/ARP 스푸핑 가능) | **하드 격리**<br>

<br>(L2 프레임 자체가 차단되므로 L3 장비(Inter-VLAN 라우팅)를 거치지 않으면 통신 불가) |
| **통신 조건** | 서로 다른 서브넷 간 통신 시 라우팅 필요 | 서로 다른 VLAN 간 통신 시 L3 라우팅(게이트웨이) 필요 |

---

**적용 범위 및 동작 원리**

**1. 서브넷 마스크의 적용 범위**

* **호스트 레벨:** 단말 OS의 네트워크 인터페이스(NIC) 설정에서 직접 지정합니다.
* **동작:** 호스트 A가 호스트 B로 핑을 보낼 때, 자신의 IP/서브넷마스크와 목적지 B의 IP를 비트 AND 연산합니다. 연산 결과 네트워크 ID가 다르면 로컬에 ARP를 날리지 않고 즉시 L3 게이트웨이(라우터)의 MAC 주소를 물어 패킷을 보냅니다.
* **보안 취약점:** 동일한 물리 L2 스위치에 연결된 두 PC가 서로 다른 서브넷 IP(`192.168.1.10/24`, `192.168.2.10/24`)를 쓰더라도, 공격자가 NIC에 Secondary IP를 추가하거나 Promiscuous 모드를 켜면 동일 L2 상의 브로드캐스트 프레임을 도청할 수 있습니다.

**2. VLAN의 적용 범위**

* **스위치 포트 및 트렁크 링크 레벨:** 네트워크 스위치의 물리 포트(Access Port) 또는 스위치 간 연결(Trunk Port)에서 설정합니다.
* **동작:** Access 포트로 들어온 이더넷 프레임에 4바이트 802.1Q 태그(VLAN ID)를 삽입합니다. 스위치는 목적지 MAC 주소를 찾을 때 **오직 동일한 VLAN ID를 가진 포트들 사이에서만 플러딩(Flooding)과 포워딩**을 수행합니다.
* **보안 격리:** 라우터나 L3 스위치의 ACL/방화벽 정책을 거치지 않는 한, L2 계층에서 패킷 자체가 전달되지 않아 완벽한 통신 격리가 이루어집니다.

---

**실무 적용 사례**

실무에서는 **"1 VLAN = 1 서브넷"을 1:1로 매핑**하여 함께 사용하는 것이 기본 표준입니다.

**사례 1: 기업 사내망 환경 (보안 및 트래픽 격리)**

* **설계:**
* **VLAN 10 (인사/재무팀):** IP 대역 `10.10.10.0/24` (Subnet Mask `255.255.255.0`)
* **VLAN 20 (일반 개발팀):** IP 대역 `10.10.20.0/24` (Subnet Mask `255.255.255.0`)
* **VLAN 30 (게스트 Wi-Fi):** IP 대역 `10.10.30.0/23` (Subnet Mask `255.255.254.0` - 대규모 단말 수용)


* **적용 효과:**
* VLAN 30 게스트 Wi-Fi 사용자가 ARP 스푸핑이나 브로드캐스트 스캔을 시도해도 VLAN 10/20의 스위치 포트로는 L2 트래픽이 유입되지 않습니다.
* 각 부서 간 통신은 상위 L3 스위치/방화벽의 게이트웨이를 반드시 거쳐야 하므로 방화벽 정책(ACL)으로 특정 포트/IP만 정밀 제어합니다.



**사례 2: 데이터센터 및 가상화/클라우드 환경**

* **설계:**
* **VLAN 100 (웹/API 서버):** `172.16.10.0/24`
* **VLAN 200 (내부 DB 클러스터):** `172.16.20.0/24`
* **VLAN 999 (서버 관리/IPMI/iLO):** `192.168.100.0/24`


* **적용 효과:**
* DB 서버는 외부 공인 인터넷이나 일반 웹 트래픽과 L2 수준에서 격리됩니다.
* 서버 관리용 IPMI 포트는 별도의 VLAN 999로 묶어 사내 VPN을 통한 관리자 IP 외에는 라우팅 자체를 차단하여 침해 사고를 방지합니다.

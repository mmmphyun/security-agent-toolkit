*2교시. 회사 네트워크의 구성 — 내부망·외부망과 DMZ*


### 점검문제

1. 내부망·외부망을 구별하는 것과 A사가 관리하는 장비 범위를 구별하는 것은 같은 기준일까? Router0과 외부 문서 SaaS를 예로 설명해 보자.

- 정답과 해설
    
    같은 기준이 아니다. 내부망·외부망은 어느 네트워크 경계를 기준으로 보는지를 말하고, 장비 관리 범위는 누가 운영하는지를 말한다. Router0은 직원 업무망 밖 방향에 연결되어 있어도 A사가 관리하는 장비이다. SaaS는 A사 직원 업무망 밖의 서비스이지만 업무에 필요한 허용 대상일 수 있다. 외부라는 이유만으로 위험이나 차단을 뜻하지 않는다.
    

2. 논리 구성도에서 회사 라우터와 인터넷 사이에 선 하나가 있다. 실제 케이블 한 개라는 뜻일까?

- 정답과 해설
    
    반드시 그렇지는 않다. 그 선은 연결 관계를 요약한 것이며 중간 장비나 회선이 생략될 수 있다. 실제 배선은 포트·케이블 정보가 있는 자료로 확인해야 한다.
    

3. 실제 장비의 어느 포트에 케이블을 꽂을지 알려면 물리 구성도와 논리 구성도 중 어떤 정보가 더 필요할까?

- 정답과 해설
    
    물리 구성도의 장비·포트·케이블 정보가 필요하다. 논리적인 요청 관계만으로 정확한 배선 위치를 결정할 수 없다.
    

4. A사 장비 관리 범위 밖의 SaaS에 회사 문서가 있다. 계정·공유 설정은 A사의 책임이 아닐까?

- 정답과 해설
    
    그렇지 않다. 그림의 테두리는 장비 관리 범위이다. SaaS의 이용 계정과 문서 공유 범위는 앞서 배운 공동 책임에 따라 A사가 관리한다.
    

5. Firewall0–Router0 연결은 직원의 SaaS 요청과 외부 방문자의 공개 웹 요청 중 어느 쪽에 필요한가?

- 정답과 해설
    
    둘 다 필요하다. 직원 요청은 Firewall0에서 Router0으로 나가고, 방문자 요청은 Router0에서 Firewall0으로 들어온다. 방향이 달라도 같은 연결을 사용하는 공통 구간이다.
    

6. 공개 웹 서버를 DMZ에 두는 이유는 무엇일까?

- 정답과 해설
    
    외부에 제공할 서비스를 직원 업무망과 분리하고 구간 사이의 통신을 제한하기 위해서이다. 공개 서비스 이용을 직원망 전체의 접근으로 확대하지 않는다.
    

7. 외부에서 공개 웹 서버의 웹페이지를 볼 수 있다. 공개 서버가 직원 PC로 시작하는 모든 새 연결도 허용된 것일까?

- 정답과 해설
    
    아니다. 두 방향은 서로 다른 요청과 정책이다. 이 예시에서는 공개 웹 접속은 허용하지만 공개 서버가 직원망으로 시작하는 새 연결은 제한한다.
    

8. 그림의 Firewall0–공개 웹 서버 연결만 사용할 수 없다. 나머지 조건은 정상이고 우회 경로가 없을 때, 직원의 외부 SaaS 요청도 반드시 실패할까?

- 정답과 해설
    
    아니다. 직원의 SaaS 요청은 Switch0 → Firewall0 → Router0 → 인터넷 쪽으로 향하고 DMZ 서버 연결을 지나지 않는다. 주어진 조건에서는 직원의 SaaS 경로가 유지되고, 그 연결을 사용하는 외부 방문자의 공개 웹 요청이 영향을 받는다.
    

9. 같은 재택 직원이 같은 SaaS 계정을 사용하면 회사 경유 여부도 항상 같을까?

- 정답과 해설
    
    항상 같지 않다. 목적지별 직접 접속 또는 회사 경유 정책과 네트워크 구성이 경로를 정한다. 계정 신원과 이동 경로는 다른 정보이다.
    

10. 구성도에서 장비 수가 적은 경로를 찾았다. 그쪽이 더 빠르다고 확정할 수 있을까?

- 정답과 해설
    
    확정할 수 없다. 회선·장비 처리·혼잡·서비스 상태와 실제 측정 조건에 따라 품질이 달라진다. 구성도는 측정할 위치를 고르는 데 도움을 주지만 성능 측정을 대신하지 않는다.
    
**공개 서버의 연결 위치가 바뀐 그림 판단하기** — 공개 웹 서버와 직원 업무망을 나눈 연결을 비교해 보자. 원래 구성에서는 직원 PC가 Switch0에 연결되고, Switch0과 공개 웹 서버는 Firewall0의 서로 다른 네트워크 구간에 연결되어 있다. 공개 웹 서버의 연결만 Firewall0에서 직원용 Switch0으로 옮겼다고 하자. 이제 직원 PC와 서버는 같은 업무망을 쓰고 별도의 분리 설정은 없다. DMZ라는 글자를 그대로 남겨도 원래의 분리 구조가 유지될까? 서버에서 직원 PC로 가는 연결을 따라가며 이유를 설명해 보자.

해설:

유지되지 않는다. 원래 구성에서는 공개 서버와 직원망 사이의 통신이 Firewall0을 거쳤다. 변경한 조건에서는 공개 서버와 직원 PC가 같은 Switch0의 같은 업무망에 연결되어, 두 장비 사이의 통신이 원래의 방화벽 분기 구조를 지나지 않는다. DMZ라는 이름보다 실제 네트워크 구간과 통제 위치가 중요하다.

구간 분리와 별도로 공개 웹 서버의 보안 업데이트와 관리 권한도 계속 관리해야 한다. 특정 내부 서비스와 통신할 필요가 있다면 그 대상과 서비스만 별도로 검토해 허용한다.

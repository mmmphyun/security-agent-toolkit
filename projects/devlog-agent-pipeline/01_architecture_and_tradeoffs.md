# DevLog Agent Pipeline: 동기 및 아키텍처 의사결정 기록

## 1. 프로젝트 시작 동기 및 문제 정의 (Why)
- SKT ALEPH 보안 자동화 부트캠프 수강 중 학습 내용을 기술 블로그로 꾸준히 기록하라는 조언을 받음.
- 그러나 단순 문법 요약이나 나이브한 예시 코드를 복사해 붙여넣는 글은 컴퓨터공학 전공생으로서 아무런 차별성을 갖지 못한다고 판단.
- "내가 문제 해결 과정에서 치열하게 고민하고 리팩터링한 주석"과 "LLM 기반 최적화 결과"를 유기적으로 엮어내고, 반복적인 글 작성 및 배포 과정을 완전히 자동화하는 Agentic 파이프라인을 구축하기로 결정.

## 2. 핵심 아키텍처 및 트레이드오프 분석 (Trade-offs)

### 플랫폼 결정: 단순 CI 스크립트 vs Antigravity 에이전트 올인원 오케스트레이션 (ADR-0002)
- **1차 시도 (GitHub Actions Cron + 단순 파이썬 스크립트):**
  - 초기에는 GitHub Actions Cron이 1회성으로 파이썬 스크립트(`generate_draft.py`)를 돌려 Gemini API를 호출하도록 설계함.
  - **한계:** 단순 텍스트 생성만으로는 외부 커리큘럼 페이지나 동적 실습 디렉토리의 심층 맥락을 파악하지 못하고, 실시간 대화형 피드백 및 자가 교정이 불가능함.
- **최종 결정 (Antigravity 올인원 오케스트레이션):**
  - 에이전트가 직접 파일 시스템 탐색, 커리큘럼 컨텍스트 로더 실행(`--fetch-curriculum`), 초기 프로토타입 분석 및 리팩터링 코드 도출, 하네스 자가 교정까지 일괄 수행하는 올인원 워크플로우로 전환.
  - **트레이드오프:** CI 서버의 완전 독립 실행을 포기하는 대신, 로컬 에이전트의 멀티모달 컨텍스트 인제스트, 실시간 대화형 검토 및 무결성 제어 능력을 확보.

### LLM 추론 엔진: Google Gemini API (3.7 Flash) & Antigravity 내장 엔진
- **결정:** 별도의 인프라 비용 없이 영구 무료 및 초고속 추론 성능을 제공하는 Gemini 계열 최신 모델(Gemini 3.7 Flash)을 채택하고, Antigravity IDE 자체 계정 엔진을 통해 zero-key 로컬 에이전트 구동 달성.

### 프론트엔드: Astro Bento Blog 기반 단일 레포지토리 (Monorepo)
- **결정:** 초경량 정적 빌드 성능과 세련된 Bento Grid 레이아웃을 갖춘 Astro Bento Blog를 채택하고, Monorepo 구조로 코드와 문서 간의 원자적 정합성(Atomicity) 보장.

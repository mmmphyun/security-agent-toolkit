# DevLog Agent Pipeline: 동기 및 아키텍처 의사결정 기록

## 1. 프로젝트 시작 동기
- SKT ALEPH 보안 자동화 부트캠프 수강 중 취업 상담에서 학습 내용을 기술 블로그로 기록하라는 조언을 받음.
- 단순 문법 요약이나 강사 예시 코드를 그대로 따라 적는 글은 컴퓨터공학 전공생으로서 아무런 차별성을 갖지 못한다고 판단.
- "내가 수업 중에 치열하게 고민하고 리팩터링한 주석"과 "AI 페어 프로그래밍 결과"를 유기적으로 엮어내고, 반복적인 글 작성/배포 과정을 완전히 자동화하는 나만의 Agentic 파이프라인을 구축하기로 결심.

## 2. 주요 기술 스택 선택 및 트레이드오프

### 플랫폼 결정: 전용 결재 웹 대시보드 vs GitHub Actions Native
- **고민:** 초고 생성 후 승인(Confirm) 단계를 위해 별도 웹 대시보드(로그인, DB, 웹소켓)를 직접 구축할까 고민함.
- **결론:** 별도 웹을 만드는 것은 유지보수 비용과 서버 호스팅 비용이 발생하는 극단적 오버엔지니어링으로 판단.
- **선택:** 개발자 표준 플랫폼인 GitHub Pull Request를 채택. 매일 18:00 KST에 Actions가 초고를 담은 PR을 자동 생성하고, 작성자는 모바일 GitHub 앱에서 검토 후 Merge 버튼 하나로 승인 및 자동 배포되도록 설계.

### LLM 엔진: Anthropic Claude vs Google Gemini
- **고민:** 한국어 뉘앙스가 뛰어난 Claude API와 빠른 속도의 Gemini API 비교.
- **결론:** 일일 1회 정기 실행 파이프라인이므로, 추가 과금 없이 영구 무료(Free Tier)로 사용 가능한 Google Gemini API 채택.

### 프론트엔드: Next.js Fumadocs vs Astro Bento Blog
- **고민:** 대기업 기술 문서 느낌의 Next.js Docsite vs 미니멀하고 세련된 Astro Bento 테마.
- **결론:** 개인 개발자 포트폴리오로서의 가독성과 세련된 레이아웃, 초경량 정적 빌드 성능을 갖춘 Astro Bento Blog 채택.

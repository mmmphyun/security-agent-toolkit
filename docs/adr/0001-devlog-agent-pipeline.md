# ADR-0001: 부트캠프 학습 기록 자동화 및 기술 아카이브 구축을 위한 Agent 파이프라인 설계

- **최종 개정일:** 2026-08-30
- **작성자:** mmmphyun
- **범위:** security-agent-toolkit 전반

## 1. 배경 및 문제 정의 (Context)

SKT ALEPH 보안 자동화 부트캠프 수강 과정에서 학습한 내용을 기술 블로그로 기록하여 취업 포트폴리오로 활용하고자 함.

### 기존 방식의 한계점 및 핵심 도전 과제
1. **변별력 부재:** 단순 파이썬 문법이나 강의 예시 코드를 그대로 요약 정리하는 글은 채용 시장에서 지원자의 실무 문제 해결력을 증명하기 어려움.
2. **반복 작업(Toil)에 따른 피로도:** 학습, 리팩터링, 검증 후 매번 수동으로 블로그 글을 작성하고 로컬에서 배포 명령어를 실행하는 과정은 본질적인 학습에 투입할 시간을 낭비시킴.
3. **AI 생성 텍스트의 신뢰도 저하:** 일반적인 LLM을 사용하여 글을 작성할 경우, 장황한 서론, 번역투, 기계적 대구 등 'AI Slop'이 발생하여 지원자의 진정성과 엔지니어링 역량에 악영향을 줌.
4. **보안 및 저작권 준수:** 부트캠프 강사의 강의 자료를 그대로 전재할 경우 지적재산권(IP) 및 비공개 커리큘럼 유출 위험이 발생함.
5. **다중 과목 디렉토리 확장성:** 1과목(AI·자동화 기초: `agent_core/`), 2과목(네트워크·ZT 운영 기초: `network_zt/`) 등 커리큘럼 확장에 따라 동일한 `day01` 파일명이 충돌할 위험 존재.

## 2. 핵심 아키텍처 의사결정 (Decisions)

### D-1. 콘텐츠 전략: Architecture Decision Record (ADR) 스타일 채택
- 단순 문법 설명과 강사 예시 코드 복제를 배제함.
- 문제 상황(Context) -> 기본 접근의 한계점(Naive Limitation) -> 전공생 관점의 리팩터링 및 의사결정(Engineering Decision) -> 아키텍처 다이어그램(Mermaid) -> 검증(Verification)의 5단계 구조로 기술 로그를 작성함.
- 작성자가 코드와 주석에 남긴 문제의식과 해결 과정을 글의 중심 축으로 설정함.

### D-2. 배포 플랫폼 및 UI: Astro Bento Blog 기반 단일 레포지토리(Monorepo)
- Next.js의 거대 문서 사이트(Docsite)가 주는 과도한 엔지니어링 느낌을 지양하고, 미니멀하면서 가독성이 높은 Astro Bento Blog 테마를 채택함.
- 코드와 블로그, 자동화 파이프라인을 하나의 레포지토리에서 관리(Monorepo)하여 코드 커밋과 문서 발행 간의 정합성과 원자성(Atomicity)을 보장함.
- 시스템 흐름 표현을 위해 Mermaid 다이어그램을 필수로 렌더링하도록 구성함.

### D-3. 완전 자동화 및 모바일 원클릭 승인 (Cron + PR Workflow)
- **전용 승인 웹 플랫폼 개발 배제:** 별도의 승인 웹 대시보드를 구축하는 것은 오버엔지니어링이며 유지보수 비용이 극심하므로 배제함.
- **GitHub Actions Native 활용:**
  - 매일 한국 시간 18:00(UTC 09:00)에 GitHub Actions Cron이 자율 구동되어 신규 실습 코드를 탐색함.
  - LLM API를 호출하여 초안을 생성하고, 하네스 검증 통과 시 자동으로 **Pull Request**를 오픈함.
  - 작성자는 스마트폰 GitHub 앱에서 내용을 확인하고 `Merge` 버튼 한 번으로 승인하며, Merge 시 GitHub Pages로 즉시 자동 배포됨.

### D-4. LLM 엔진 및 비용 모델: Google Gemini API 무료 티어 채택
- 일일 1회 정기 실행에 최적화된 Google Gemini 1.5 Flash API를 채택함.
- Google AI Studio의 Free Tier 한도(분당 15회, 일 1,500회) 내에서 동작하여 추가 인프라 및 API 비용 0원으로 영구 구동되도록 설계함.

### D-5. 무결성 보장을 위한 하네스(Harness) 및 거버넌스
- 프롬프트 레벨의 지시문에만 의존하지 않고, 생성된 마크다운을 결정론적(Deterministic)으로 검증하는 파이썬 Linter(`pipeline/harness.py`)를 파이프라인에 배치함.
- 검증 기준: 이모지(Emoji) 완전 배제, 필수 5대 ADR 섹션 존재 여부, Mermaid 문법 유효성 검사, AI 상투어구 차단.

### D-6. 다중 과목 메타데이터 격리
- 과목별 접두사(`c01-agent-core-dayXX`, `c02-network-zt-dayXX`) 규칙을 확립하여 다중 과목 간 동일 일차(day01) 파일명 충돌을 원천 차단함.
- 각 실습 일자별로 필요한 데이터(`logs/`)는 각 날짜 디렉토리 내부로 격리하여 독립적인 재현성을 확보함.

## 3. 결과 및 기대 효과 (Consequences)

### 긍정적 효과
- **개발자 경험(DX) 극대화:** 작성자는 평소처럼 코드와 주석만 커밋하면 되며, 명령어 실행 없이 모바일 알림과 원클릭 승인만으로 블로그 운영이 완료됨.
- **포트폴리오 변별력:** 보안 자동화 과정에 부합하게 '자신의 업무 프로세스를 LLM과 Git Actions 파이프라인으로 자동화한 실전 프로젝트'로 어필 가능.
- **문서 무결성:** 하네스 검증을 통해 일관된 톤앤매너와 정확한 기술 용어를 유지함.

### 고려사항 및 제약
- 새로운 일차의 글을 발행할 때마다 주석에 문제의식과 해결 근거가 충분히 기록되어 있어야 고품질의 초고가 도출됨.
- GitHub Repository Secrets에 `GEMINI_API_KEY`가 사전에 등록되어 있어야 CI 워크플로우가 정상 실행됨.

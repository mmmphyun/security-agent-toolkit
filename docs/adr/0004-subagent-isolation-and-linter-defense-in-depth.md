# ADR-0004: 서브에이전트 컨텍스트 격리, 하네스 린터 심층 방어 및 토큰 최적화 아키텍처

- **상태:** 승인됨 (Accepted)
- **최종 개정일:** 2026-09-01
- **작성자:** mmmphyun
- **범위:** `pipeline/harness.py`, `pipeline/config/whitelist.json`, `AGENTS.md`, `tests/test_harness.py`

## 1. 배경 및 문제 정의 (Context)

블로그 작성 파이프라인의 실운영 및 연속 스케줄링 과정에서 다음 4가지 구조적/품질적 결함이 식별됨:

1. **단일 세션 장기 운영 시 컨텍스트 과부하 (Context Bloat & Token Inefficiency):**
   - 매일 정기 스케줄이 동일 세션에서 반복 구동될 때, 수만 줄의 실습 소스코드, 커리큘럼 명세, Astro 빌드 로그, 초안 전문이 대화 히스토리에 누적됨.
   - 이로 인해 토큰 비용 및 추론 레이턴시가 급증하고, 이전 일차(Day 05, Day 06)의 맥락이 신규 일차로 오염되는 컨텍스트 블리드(Context Bleed) 위험 발생.
2. **AI 번역투 괄호 영단어 병기 누락 (`im-not-ai` 거버넌스 위반):**
   - 프롬프트 지침만으로는 `경보(Alert)`, `도구(Tool)`와 같은 기계 번역투 괄호 표기를 모델이 자의적으로 통과시키는 품질 결함 발생.
3. **하네스 린터의 경직성과 유지보수 부채:**
   - 파이썬 소스코드 내에 화이트리스트가 하드코딩되어 신규 기술 용어 추가 시 코드를 매번 수정해야 함.
   - '뿐만 아니라', '을 통해' 등 일반 한국어 문장까지 획일적으로 차단할 경우 심각한 오탐(False Positive)과 문장 왜곡이 발생함.
4. **스킬 미로드 및 지침 건너뛰기 (Procedural Drift):**
   - 에이전트가 `exploring-codebases`, `searching-codebases`, `humanize-korean` 스킬의 `SKILL.md`를 사전에 로드하지 않고 자체 가중치로 직독직해하여 품질 표준을 미달하는 문제 발생.

## 2. 핵심 아키텍처 의사결정 (Decisions)

### D-1. 단발성 서브에이전트(`invoke_subagent`) 컨텍스트 격리 및 토큰 최적화
- 메인 세션의 메모리 오염을 원천 차단하기 위해, 1단계(타겟 스캔) 이후 무거운 작업(인제스트, 5단 초안 작성, 하네스/빌드 자가 교정)을 **독립된 1회용 메모리를 가진 서브에이전트**에게 위임함.
- **본문 전문 출력 생략:** 서브에이전트는 검증 완료 후 본문 전문(수천 토큰)을 대화창에 출력하지 않고, **생성된 파일 마크다운 링크, 핵심 의사결정 요약, 검증 결과만 반환**하여 메인 세션 토큰 소비량을 80% 이상 절감함.

### D-2. 스킬 선행 로드(Pre-loading) 체크리스트 표준화
- 서브에이전트 호출 시 1턴에서 반드시 다음 3개 스킬의 `SKILL.md`를 `view_file`로 먼저 호출하도록 프롬프트 템플릿을 고정함:
  1) `exploring-codebases` (레포지토리 구조 및 멘탈 모델 수립)
  2) `searching-codebases` (AST 데코레이터/클래스 정밀 슬라이싱)
  3) `humanize-korean` (10대 AI 티 패턴 제거 및 테크니컬 평어체)

### D-3. 하네스 린터의 4중 심층 방어 (Defense-in-Depth)
1. **괄호 영단어 병기 하드 게이트 (`check_parentheses_english` - `Hard Error`):**
   - `한글(English)` 형태의 번역투 병기를 기계적으로 차단(`exit 1`).
2. **대문자 기술 약어 정규식 자동 허용 (`ACRONYM_PATTERN`):**
   - `r"^[A-Z0-9]{2,6}$"` 패턴을 도입하여 `JWT`, `AES`, `RSA`, `RFC`, `SSO`, `WAF` 등 공인 기술 약어는 별도 등록 없이 자동 허용.
3. **화이트리스트 외부 JSON 설정 분리 (`pipeline/config/whitelist.json`):**
   - 고유명사 및 프레임워크 목록을 파이썬 코드에서 설정 파일로 분리(Decoupling).
4. **복합 대구 소프트 경고 (`Soft Warning`):**
   - 단순 어휘가 아닌 양산형 복합 패턴(`뿐만 아니라 .+도 .+을 통해`)만 선별하여 `[알림]` 로그로 출력(오탐 및 과교정 방지).

### D-4. 17:00 정기 스케줄 및 무질문 자율 직행(Zero-Question Direct Execution) 확립
- 평일 17:00 정기 스케줄 트리거 시 진행 여부를 사용자에게 되묻지 않고 1단계부터 4단계까지 전자율 완주 후 5단계 컨펌 게이트웨이에서만 대기함.

## 3. 결과 및 기대 효과 (Consequences)

### 긍정적 효과
1. **무한 확장 가능한 세션 수명:** 서브에이전트 격리를 통해 메인 대화 세션에 소스코드/빌드 로그가 쌓이지 않아 수개월간 동일 세션을 유지해도 컨텍스트 과부하가 발생하지 않음.
2. **기계적 무결성 보장:** 괄호 영단어 병기가 린터 단계에서 100% 차단되며, 정상적인 한국어 기술 문장은 오탐 없이 보존됨.
3. **유지보수성 향상:** 신규 기술 용어 추가 시 파이썬 코드 수정 없이 `whitelist.json`만 갱신하면 됨.
4. **토큰 비용 대폭 절감:** 초안 전문 출력 생략으로 회차당 수천 토큰의 API 비용을 절감.

### 제약 사항 및 운영 수칙
- `docs/posts/` 문서 커밋 시 사전 하네스 통과가 필수이며, 사용자 명시적 컨펌 없이는 커밋 및 원격 푸시가 엄격히 차단됨.

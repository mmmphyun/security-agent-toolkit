# ADR-0003: 블로그 다중 키 정렬 및 Mermaid 런타임 구문 검증 하네스 강화

- **상태:** 승인됨 (Accepted)
- **최종 개정일:** 2026-09-01
- **작성자:** mmmphyun
- **범위:** `pipeline/harness.py`, `blog/`, `docs/posts/`, `AGENTS.md`

---

## 1. 배경 및 문제 정의 (Context)

블로그 운영 및 실습 기록 작성 과정에서 다음 3가지 기술적 결함이 식별됨:

1. **SSG 빌드와 클라이언트 렌더링 분리로 인한 Mermaid 런타임 오류 누락:**
   - Astro는 정적 사이트 생성기(SSG)이므로, 빌드 시점(`npm run build`)에는 Mermaid 코드를 파싱하지 않고 단순 HTML `<pre>` 태그로 변환함.
   - 실제 다이어그램 파싱 및 SVG 렌더링은 브라우저 런타임(`mermaid.render()`)에서 비동기로 실행됨.
   - 기존 `harness.py`는 ```` ```mermaid ```` 문자열의 존재 여부만 검사하여, 라벨 괄호 미인용이나 `&` 다중 결합자 등 브라우저를 다운시키는 구문 오류를 CI/빌드 단계에서 사전에 잡지 못함.
2. **동일 발행일(`pubDate`)에 따른 블로그 정렬 비결정성(Non-deterministic Sort):**
   - 1~5일차 포스트가 동일한 날짜(`2026-08-30`)로 작성되어 있어, JavaScript 정렬 엔진이 파일 시스템 로드 순서대로 포스트를 무작위로 뒤섞어 렌더링함.
3. **독립 기술 Q&A / 리서치 주석의 수집 누락:**
   - 실습 코드 라인과 직접 1:1로 매핑되지 않은 고품질 보안 아키텍처 리서치 주석(`mini_agent.py` 하단 Q&A 등)이 5단 고정 템플릿 구조에서 제외되는 문제 발생.

---

## 2. 핵심 아키텍처 의사결정 (Decisions)

### D-1. `pipeline/harness.py` Mermaid 런타임 구문 파서 탑재
- 단순 문자열 매칭을 폐기하고, 마크다운 내 Mermaid 코드 블록을 정밀 파싱하는 Linter 로직 구축:
  - 다이어그램 선언 유효성(`flowchart`, `sequenceDiagram` 등).
  - 엣지 라벨 내 특수문자/괄호(`()`, `{}`, `[]`, `/`) 미인용 검출 (`|"라벨"|` 강제).
  - 브라우저 렌더링을 깨뜨리는 `&` 다중 노드 연결자(`A & B --> C`) 검출 및 개별 간선 분리 강제.
  - 괄호(`[]`, `{}`) 열림/닫힘 쌍 일치 검사.

### D-2. 블로그 아카이브 다중 키 정렬 (Multi-key Sorting) 도입
- `blog/src/pages/blog/[...page].astro`의 정렬 로직을 2차 다중 키 방식으로 개편:
  - 1차 정렬: 발행일(`pubDate`) 역순 (최신순).
  - 2차 정렬: `pubDate` 동일 시 `slug`(과목 접두사 및 일차) 오름차순 (`a.data.slug.localeCompare(b.data.slug)`).
- 1~6일차 실습 포스트의 `pubDate`를 실제 진행 일자(`2026-08-25` ~ `2026-08-31`)로 순차 재배치하여 명확한 타임라인 확보.

### D-3. 독립 기술 Q&A / 리서치 주석의 하이브리드 배치 거버넌스 (`AGENTS.md` 섹션 4)
- 소스코드에 작성된 심층 리서치/Q&A 주석(Zero Trust, Dual LLM 패턴, Blast Radius 제어 등)을 포스트 내 다음 위치에 서브섹션으로 승화 배치:
  - `## 4. 엔지니어링 의사결정 및 리팩터링` ➔ `### 심층 방어 아키텍처` 독립 서브섹션으로 기술.
  - `## 5. 검증 및 회고` ➔ `### 캡스톤 프로젝트 및 실무 확장 로드맵`으로 연계 서술.

---

## 3. 결과 및 기대 효과 (Consequences)

1. **무결점 다이어그램 렌더링:** 브라우저 런타임 오류가 발생할 수 있는 Mermaid 구문 결함을 로컬 하네스 단계에서 100% 사전 차단함.
2. **정갈한 아카이브 타임라인:** 과목 및 일차별로 정확한 연대기적/논리적 순서로 블로그 목록이 렌더링됨.
3. **기술적 깊이 극대화:** 단순 수업 실습 요약을 넘어 실무 보안 아키텍처 수준의 독자적 리서치 내용이 블로그 핵심 섹션에 유기적으로 통합됨.
